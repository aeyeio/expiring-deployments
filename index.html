Expiring Deployments

Automate cleanup for Kubernetes preview namespaces, feature branches, QA sandboxes, and ephemeral Helm releases. Expiring Deployments is a Helm chart that ships a CronJob (backed by Lottie motion visuals) to enforce TTL policies, honor protected namespaces, and log every decision.

What it does well

  • Dry-run first, so audits show actions without deleting resources.
  • Metadata contract: expiring-deployments.io/enabled, expires-at, or ttl-hours.
  • Supports preview branches, QA clusters, and CI-created namespaces via selectors.

Install

GitHub Pages:
helm repo add expiring-deployments https://aeyeio.github.io/expiring-deployments
helm install expiring-deployments expiring-deployments/expiring-deployments --version 0.1.3

Harbor OCI:
helm registry login harbor.localhost ... --insecure
helm install expiring-deployments oci://harbor.localhost/library/expiring-deployments/expiring-deployments --version 0.1.3 --insecure-skip-tls-verify

Usage flows

  • PR previews: annotate pr-1234 namespace with TTL; CronJob deletes it after merge + TTL.
  • Helm leases: include a TTL ConfigMap lease in a shared namespace; the CronJob uninstalls the release when the lease expires.
  • Manual sandboxes: install the chart with a TTL and let the CronJob remove the namespace later.

How to uninstall

  • helm uninstall expiring-deployments to remove the CronJob and RBAC.
  • Drifted namespaces can be deleted with kubectl delete ns <name>.
  • Helm leases remain; the CronJob stops after uninstall.

As-is, no guarantees. Use the chart in non-production clusters first; review the CronJob logs before enabling real deletions.
